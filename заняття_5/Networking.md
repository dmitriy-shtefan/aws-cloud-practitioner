# **Заняття 7: Networking & Content Delivery**

---

## **1. Amazon VPC (Virtual Private Cloud) та Subnets**

**Amazon VPC (Virtual Private Cloud)** — це логічно ізольований сегмент хмари AWS у межах одного регіону, який повністю контролюється клієнтом і дозволяє запускати ресурси AWS у визначеній вами віртуальній мережі. 

*   **CIDR Block**: При створенні VPC ви визначаєте діапазон її IP-адрес за допомогою безкласової адресації **CIDR (Classless Inter-Domain Routing)**. Наприклад, блок `/16` (як-от `10.0.0.0/16`) є значно більшим і виділяє більше адрес, ніж маска `/24` (як-от `10.0.0.0/24`).
*   **Subnets (підмережі)** — це логічний розподіл вашого загального адресного простору VPC на менші мережеві сегменти. Кожна підмережа обов'язково асоціюється лише з однією конкретною **Availability Zone (AZ)**.
    *   **Public Subnet** (публічна підмережа) — має налаштований маршрут до Інтернету. Будь-який інстанс, запущений у такій підмережі, може автоматично отримувати публічну IP-адресу.
    *   **Private Subnet** (приватна підмережа) — підмережа, ресурси якої повністю закриті від прямого доступу з публічного Інтернету та не отримують публічних IP-адрес за замовчуванням.

## **2. Route Tables, Internet Gateway та NAT Gateway**

Маршрутизація трафіку всередині VPC забезпечується трьома основними компонентами:

*   **Route Tables (таблиці маршрутизації)** — це набір правил (маршрутів), які вказують, куди саме має спрямовуватися вихідний мережевий трафік із вашої підмережі. За замовчуванням кожна підмережа містить локальний маршрут (**local route**) для внутрішнього обміну даними між ресурсами VPC.
*   **Internet Gateway (IGW)** — це резервований і масштабований мережевий компонент, який приєднується до вашої VPC для забезпечення двостороннього зв'язку між ресурсами публічних підмереж та Інтернетом. Щоб зробити підмережу публічною, у її таблиці маршрутизації додається маршрут за замовчуванням (**default route**) — `0.0.0.0/0`, який вказує на ваш IGW.
*   **NAT Gateway (Network Address Translation Gateway)** — Загалом у хмарах він використовується для того, щоб інстанси з приватних підмереж могли безпечно виходити в Інтернет (наприклад, для завантаження оновлень ОС), повністю блокуючи будь-які вхідні запити з боку Інтернету.

## **3. Security Groups проти Network ACL (NACL)**

AWS надає два незалежні рівні мережевих фаєрволів для захисту вашої інфраструктури:

```
                      [ Інтернет ]
                           │
  ─────────────────────────┼───────────────────────── (Рівень Subnet)
                    ┌──────▼──────┐
                    │ Network ACL │ (Stateless, Allow/Deny, Subnet-level)
                    └──────┬──────┘
  ─────────────────────────┼───────────────────────── (Рівень Instance)
                    ┌──────▼───────┐
                    │Security Group│ (Stateful, Only Allow, Instance-level)
                    ├──────────────┤
                    │ EC2 Instance │
                    └──────────────┘
```

### **Security Groups (SG)**
Групи безпеки діють як віртуальний фаєрвол безпосередньо на рівні конкретного інстансу (**instance level**).
*   **Only Allow Rules**: За замовчуванням весь вхідний трафік заблокований. Ви можете створювати **виключно правила дозволу (Allow rules)**. Правила заборони (Deny) не підтримуються.
*   **Stateful (збереження стану)**: Якщо ви дозволили певний вхідний трафік (наприклад, HTTP-запит на порт 80), вихідний трафік-відповідь буде випущений автоматично, незалежно від вихідних правил.
*   **Неможливо заблокувати IP**: Оскільки SG не мають правил типу Deny, ви не можете заблокувати одну конкретну зловмисну IP-адресу.

### **Network ACL (NACL)**
Списки контролю доступу діють як фаєрвол на рівні всієї підмережі (**subnet level**).
*   **Allow & Deny Rules**: Підтримують як правила дозволу (**Allow**), так і правила заборони (**Deny**). Це ваш головний інструмент для блокування конкретних зловмисних IP-адрес на підходах до мережі.
*   **Порядок обробки**: Усі правила в NACL нумеруються (наприклад, правило 100, 110, 150) і обробляються строго по порядку від найменшого номера до найбільшого.
*   *Stateless (без збереження стану)*: У транскрипті зазначено, що хоча AWS любить запитувати про різницю stateless/stateful, детальні питання на цьому рівні зазвичай не зустрічаються на іспиті Cloud Practitioner. Проте корисно пам'ятати, що NACL є **stateless**, тобто вхідний та вихідний трафік мають бути дозволені окремо.

## **4. Amazon Route 53 та Amazon CloudFront**

### **Amazon Route 53**
Це повністю керована глобальна служба доменних імен **DNS (Domain Name Service)**.
*   Вона реєструє та керує вашими доменними іменами (наприклад, `exampro.co`).
*   Route 53 перетворює буквені назви сайтів на IP-адреси та спрямовує користувачів до відповідних ресурсів, таких як балансувальники навантаження (**Application Load Balancers**) чи дистрибуції CloudFront.

### **Amazon CloudFront**
Це глобальна мережа доставки контенту **CDN (Content Delivery Network)**, яка кешує статичні копії популярних файлів (відео, зображення, сторінки) якомога ближче до кінцевих користувачів.
*   **Edge Locations** — периферійні дата-центри, які безпосередньо кешують популярні файли. Вони працюють як «з'їзди» (**off-ramps**) з приватної мережі AWS до користувача.
*   **Regional Edge Caches** — проміжні кеш-локації з набагато більшим обсягом пам'яті для зберігання менш популярних файлів, що дозволяє уникнути зайвих запитів до оригінального сервера.
*   **Origins** (оригінальні сервери) — джерела контенту, звідки CloudFront забирає файли для кешування (наприклад, бакети Amazon S3, сервери EC2 або API Gateway).
*   **Geographical Restriction** (географічне обмеження) — можливість блокувати або дозволяти роздачу контенту для конкретних країн (наприклад, блокування доступу для UK через правила GDPR).
*   **Invalidation** (інвалідація) — функція примусового очищення застарілого кешу на Edge-локаціях до закінчення стандартного терміну його дії (TTL).
*   **Edge Functions**: CloudFront підтримує виконання легкого коду прямо на периферійних локаціях (через **Lambda@Edge** або **CloudFront Functions**), що забезпечує мінімальну затримку без холодної зупинки (cold start).

## **5. Глобальні мережеві сервіси та інтеграції**

Коли ви будуєте гібридні або глобальні архітектури, використовуються такі мережеві рішення:

*   **AWS VPN (Virtual Private Cloud)** — створює безпечний шифрований тунель через публічний Інтернет за допомогою протоколу **IPSec**.
    *   **AWS Site-to-Site VPN** — підключає вашу локальну мережу офісу чи дата-центру безпосередньо до VPC.
    *   **AWS Client VPN** — дозволяє віддаленим працівникам безпечно підключатися до ресурсів AWS або вашої on-premise інфраструктури.
*   **AWS Direct Connect (DX)** — виділена приватна лінія фізичного зв'язку (оптоволоконний кабель) між вашим дата-центром та інфраструктурою AWS. 
    *   Забезпечує наднизьку затримку (latency), стабільну швидкість від 50 Mbps до 10 Gbps та знижує витрати на трафік.
    *   **УВАГА**: Це приватне з'єднання, але воно **не є шифрованим** за замовчуванням. Для повної безпеки поверх Direct Connect рекомендується налаштовувати AWS VPN.
*   **AWS Global Accelerator** — мережевий сервіс, який оптимізує шлях користувачів до ваших серверів. Він використовує найближчу **Edge Location** як швидкісну точку входу (**on-ramp**), перенаправляючи трафік користувача з публічного інтернету на приватну швидкісну мережу AWS (backbone network).
*   **VPC Endpoints (PrivateLink)** — інтерфейсні кінцеві точки (interface endpoints), які дозволяють ресурсам вашої VPC безпечно спілкуватися з іншими сервісами AWS (наприклад, S3 або DynamoDB), не виходячи в публічний Інтернет і залишаючи весь трафік всередині приватної мережі AWS.
