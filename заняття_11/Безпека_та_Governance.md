# Безпека та governance в AWS

## 1. Карта сервісів: одна потреба, один вибір

| Сервіс або інструмент | Одна відмінна задача | Ключова підказка |
| --- | --- | --- |
| AWS Key Management Service (KMS) | Керувати ключами шифрування | Ключ шифрування |
| AWS Secrets Manager | Керувати секретом із налаштованою автоматичною ротацією | Зміна пароля бази даних |
| AWS Systems Manager Parameter Store | Централізовано зберігати параметри конфігурації | URL або назва середовища |
| AWS WAF | Фільтрувати HTTP(S)-запити до вебзастосунку | SQL injection |
| AWS Shield | Захищати від DDoS-атак | Перевантаження потоком трафіку |
| Amazon GuardDuty | Виявляти підозрілу або шкідливу активність | Ознаки загрози |
| Amazon Inspector | Виявляти вразливості програмного забезпечення | Вразливий пакет |
| Amazon Macie | Виявляти чутливі дані в Amazon S3 | Персональні дані у файлах |
| AWS Security Hub | Об'єднувати та пріоритезувати результати перевірок безпеки | Спільний огляд findings |
| AWS Artifact | Отримувати звіти про відповідність AWS стандартам | Звіт аудитора |
| AWS Organizations | Організовувати централізоване управління кількома AWS-акаунтами | Акаунти та OU |
| Service Control Policies (SCP) | Встановлювати верхню межу дозволів для акаунтів організації | Організаційна заборона |

## 2. Ключі, секрети та конфігурація

### AWS KMS

**Задача:** керувати ключами, які використовуються для шифрування даних.

**Приклад:** компанія зберігає документи в S3 та хоче контролювати використання ключа, яким захищається їх шифрування. Для керування таким ключем підходить KMS.

**Що запам'ятати:** ключ шифрування і пароль бази даних мають різні призначення. KMS керує криптографічними ключами; зберігання пароля застосунку не є його відмінною задачею в цьому матеріалі.

Джерело: [AWS KMS](https://docs.aws.amazon.com/kms/latest/developerguide/overview.html).

### AWS Secrets Manager

**Задача:** керувати секретом, для якого потрібна автоматична ротація.

**Приклад:** застосунок підключається до бази даних. Пароль зберігається в Secrets Manager, а налаштована ротація регулярно його змінює. Застосунок отримує актуальний секрет під час роботи замість зберігання пароля в коді.

**Що запам'ятати:** ротація означає зміну секрету. Її потрібно налаштувати; саме створення секрету не вмикає автоматичну зміну пароля.

Джерело: [AWS Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html).

### AWS Systems Manager Parameter Store

**Задача:** централізовано зберігати параметри конфігурації застосунку.

**Приклад:** параметр `/course/dev/api-url` містить адресу API для тестового середовища. Застосунок читає значення з Parameter Store, тому адресу не потрібно вписувати в код.

**Що запам'ятати:** Parameter Store є можливістю Systems Manager. Він також підтримує зашифровані значення `SecureString` із використанням KMS. Проте в задачі про автоматичну ротацію пароля бази даних відмінною відповіддю є Secrets Manager.

Джерело: [Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html).

## 3. Захист вебзастосунку

### AWS WAF

**Задача:** фільтрувати HTTP(S)-запити за правилами вебзахисту.

**Приклад:** інтернет-магазин отримує запити з ознаками SQL injection. Правила AWS WAF допомагають виявляти та блокувати такі запити до захищеного вебресурсу.

**Що запам'ятати:** WAF аналізує вебзапити. Він не виправляє вразливий код застосунку.

Джерело: [AWS WAF](https://docs.aws.amazon.com/waf/latest/developerguide/what-is-aws-waf.html).

### AWS Shield

**Задача:** захищати від distributed denial of service (DDoS), тобто розподілених атак на доступність.

**Приклад:** зловмисники спрямовують великий потік трафіку, щоб зробити сайт недоступним. Shield призначений для захисту від DDoS.

**Що запам'ятати:** Shield Standard надає базовий автоматичний захист без додаткової плати. Shield Advanced є платним розширеним варіантом. У межах теми достатньо пов'язати Shield із DDoS, а WAF із правилами перевірки вебзапитів. Ці сервіси можуть працювати разом.

Джерело: [AWS Shield](https://docs.aws.amazon.com/waf/latest/developerguide/shield-chapter.html).

## 4. Виявлення проблем безпеки

### Amazon GuardDuty

**Задача:** виявляти підозрілу або шкідливу активність в AWS-середовищі.

**Приклад:** EC2-інстанс встановлює з'єднання з адресою, пов'язаною зі шкідливою активністю. GuardDuty може сформувати finding про можливу загрозу.

**Що запам'ятати:** finding є результатом виявлення проблеми. Виявлення загрози не означає, що вона автоматично усунута.

Джерело: [Amazon GuardDuty](https://docs.aws.amazon.com/guardduty/latest/ug/what-is-guardduty.html).

### Amazon Inspector

**Задача:** виявляти відомі вразливості програмного забезпечення в підтримуваних робочих навантаженнях.

**Приклад:** у пакеті, встановленому на EC2, є відома вразливість із номером CVE. Inspector допомагає виявити її, щоб команда могла визначити пріоритет оновлення.

**Що запам'ятати:** Inspector шукає вразливості, а GuardDuty шукає ознаки підозрілої активності. Inspector не встановлює виправлення замість адміністратора.

Джерело: [Amazon Inspector](https://docs.aws.amazon.com/inspector/latest/user/what-is-inspector.html).

### Amazon Macie

**Задача:** виявляти чутливі дані в об'єктах Amazon S3.

**Приклад:** серед файлів у S3 потрібно знайти документи з персональними даними, наприклад номерами платіжних карток. Macie аналізує підтримувані об'єкти та повідомляє про знайдені дані.

**Що запам'ятати:** основна підказка для цієї теми: чутливі дані у S3. Macie не є універсальним сканером усіх баз даних і не шифрує знайдені файли автоматично.

Джерело: [Amazon Macie](https://docs.aws.amazon.com/macie/latest/user/what-is-macie.html).

### AWS Security Hub

**Задача:** об'єднувати та пріоритезувати результати перевірок безпеки для спільного огляду.

**Приклад:** команда отримує findings від GuardDuty, Inspector та Macie. Security Hub допомагає бачити проблеми разом і визначати, які потребують уваги першими.

**Що запам'ятати:** Security Hub дає спільну картину проблем, але спеціалізовані сервіси виконують свої перевірки. В актуальних матеріалах AWS також використовується назва Security Hub CSPM для можливостей управління станом безпеки та агрегації findings. Для цієї теми достатньо відмінної задачі: централізований огляд результатів.

Джерела: [Security Hub FAQ](https://aws.amazon.com/security-hub/faqs/), [інтеграції Security Hub CSPM](https://docs.aws.amazon.com/securityhub/latest/userguide/securityhub-internal-providers.html).

## 5. Документи про відповідність

### AWS Artifact

**Задача:** отримувати звіти про відповідність AWS вимогам стандартів.

**Приклад:** аудитор просить звіт SOC про контрольні заходи AWS. Такий документ можна отримати через AWS Artifact.

**Що запам'ятати:** звіт AWS не підтверджує автоматично відповідність застосунку клієнта. Клієнт відповідає за власні налаштування та контрольні заходи згідно з моделлю спільної відповідальності.

Джерело: [AWS Artifact](https://docs.aws.amazon.com/artifact/latest/ug/what-is-aws-artifact.html).

## 6. Базові governance-інструменти

Governance означає організацію управління AWS-середовищем і встановлення спільних правил його використання.

### AWS Organizations

**Задача:** організовувати централізоване управління кількома AWS-акаунтами.

**Приклад:** компанія має окремі акаунти для розробки, тестування та виробничого середовища. Organizations об'єднує їх в організацію; акаунти можна групувати в organizational units (OU), тобто організаційні одиниці.

**Що запам'ятати:** AWS-акаунт є окремим середовищем ресурсів та доступу. OU є групою акаунтів, а не групою IAM-користувачів.

Джерело: [AWS Organizations](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_introduction.html).

### Service Control Policies (SCP)

**Задача:** встановлювати верхню межу дозволів у межах AWS Organizations.

**Приклад:** компанія забороняє вимикати GuardDuty в акаунтах певної OU. SCP з відповідним явним `Deny` обмежує таку дію навіть для IAM-адміністратора акаунту, на якого поширюється політика.

**Що запам'ятати:** SCP не надає дозволів. Потрібний дозвіл усе одно має бути наданий відповідною політикою доступу, наприклад IAM. Явну заборону SCP не можна скасувати дозволом IAM.

На базовому рівні важливі дві межі: SCP використовуються в організації з увімкненими усіма можливостями (all features); вони не обмежують користувачів і ролі management account. SCP застосовуються до member accounts, зокрема до їх root user, але не до service-linked roles. Це організаційні обмеження, а не заміна IAM.

Джерело: [Service control policies](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html).
