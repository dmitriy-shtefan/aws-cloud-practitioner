# **Storage — Amazon S3 (Simple Storage Service)**

**Amazon S3 (Simple Storage Service)** — це один із найперших і найважливіших сервісів AWS, який є повністю керованим безсерверним об'єктним сховищем (**serverless object storage service**).

---

## **1. Концепція об'єктного зберігання (Object Storage)**

На відміну від блочних та файлових систем, об'єктне сховище управляє даними як окремими сутностями (об'єктами).

```
  Файлова система (EFS)             Блочне сховище (EBS)            Об'єктне сховище (S3)
   [Ієрархія папок]                  [Сектори та треки]               [Плаский простір]
      └── Папка                         └── Блок 1                      ├── Об'єкт A (Key, Value)
           └── Файл                         └── Блок 2                  └── Об'єкт B (Metadata, ID)
```

*   **S3 Buckets (Бакети)** — логічні контейнери для зберігання об'єктів.
    *   **Universal Namespace**: Історично назви бакетів мали бути глобально унікальними серед усіх користувачів AWS у світі (подібно до доменних імен).
    *   **Account Regional Namespace**: Нова опція, яка дозволяє створювати бакети, чиї імена обмежені (scoped) лише вашим акаунтом та регіоном, що усуває проблему конфлікту назв.
*   **S3 Objects (Об'єкти)** — файли, які ви завантажуєте в бакет. Кожен об'єкт складається з:
    *   **Key**: Унікальне ім'я об'єкта (шлях до нього, наприклад, `images/photo.png`).
    *   **Value**: Сам вміст файлу (послідовність байтів).
    *   **Version ID**: Унікальний ідентифікатор версії (якщо увімкнено **Versioning**).
    *   **Metadata**: Набір пар "ключ-значення" з додатковою інформацією про файл (наприклад, тип файлу чи авторські теги).
*   **Розмір файлів**: Один об'єкт в S3 може мати розмір від **0 bytes до 5 TB**. Загальний обсяг сховища в бакеті є абсолютно **лімітованим лише вашим гаманцем (unlimited storage)**.

## **2. Класи зберігання (S3 Storage Classes)**

AWS пропонує різні класи зберігання, що дозволяє оптимізувати витрати залежно від частоти доступу до ваших даних:

| Клас зберігання | Опис та сценарії використання | Доступність (Availability) | Durability | Кількість AZ | Особливості |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **S3 Standard** | Дефолтний клас для часто використовуваних даних (зображення на сайтах, активні медіафайли). | **99.99%** | **11 9's (99.999999999%)** | **≥ 3 AZs** | Миттєвий доступ. |
| **S3 Intelligent-Tiering** | Автоматично переміщує файли між гарячими та холодними класами за допомогою **Machine Learning (ML)** на основі аналізу використання. | Залежить від поточного класу | **11 9's** | **≥ 3 AZs** | Немає плати за переміщення даних. |
| **S3 Standard-IA** | Для даних, які потрібні рідко (Infrequent Access, наприклад, раз на місяць), але доступ має бути миттєвим. | **Висока** | **11 9's** | **≥ 3 AZs** | Дешевше зберігання, але стягується плата за зчитування (**retrieval fee**). |
| **S3 One Zone-IA** | Аналог Standard-IA, але дані зберігаються в межах однієї зони доступності (**Single AZ**). | **Нижча за Standard** | **11 9's** | **1 AZ** | На 20% дешевше за Standard-IA, але у разі катастрофи в AZ дані будуть втрачені. |
| **S3 Glacier Flexible Archive** | Холодне архіваційне сховище. | Архів | **11 9's** | **≥ 3 AZs** | Отримання даних триває від **кількох хвилин до кількох годин**. |
| **S3 Glacier Deep Archive** | Найдешевше сховище в AWS для довгострокових архівів (на роки). | Архів | **11 9's** | **≥ 3 AZs** | Затримка при отриманні даних становить **12 годин**. |
| **S3 Outposts** | Для локального зберігання об'єктів на обладнанні AWS Outposts у вашому дата-центрі. | Локально | — | Локально | Використовується для суворої локалізації даних. |

## **3. Безпека, доступ та функції S3**

*   **Block Public Access (Блокування публічного доступу)** — захисний бар'єр, який за замовчуванням увімкнений для всіх нових бакетів, запобігаючи випадковому витоку конфіденційних даних в Інтернет.
*   **Bucket Policies vs ACLs**:
    *   **Bucket Policies**: Сучасні JSON-документи політик доступу на рівні всього бакета (найкраща практика).
    *   **Access Control Lists (ACLs)**: Застарілий метод керування доступом на рівні окремих об'єктів (використовується лише для legacy-workflow).
*   **Bucket Versioning (Версіонування)** — збереження кількох версій об'єкта під одним ключем. Захищає дані від випадкового перезапису, видалення чи атак зловмисників (ransomware).
*   **Object Lock** — режим, що реалізує модель **WORM (Write Once, Read Many)**, блокуючи будь-яку можливість видалення чи перезапису об'єктів протягом визначеного часу.
*   **Life Cycle Rules** — правила автоматизації, які переводять старі об'єкти в дешевші класи (наприклад, Standard -> Glacier через 30 днів) або повністю видаляють їх.
*   **Pre-signed URLs** — генерація тимчасових посилань з обмеженим терміном дії (наприклад, 5 хвилин), за якими користувачі можуть безпечно завантажити або скачати приватний файл.
*   **S3 Transfer Acceleration** — функція прискорення завантаження великих файлів, яка використовує **Edge Locations** як швидкісні точки входу (**on-ramps**) до приватної мережі AWS.

## **4. Порівняння S3 з іншими типами сховищ AWS**

| Критерій порівняння | Amazon S3 | Amazon EBS | Amazon EFS |
| :--- | :--- | :--- | :--- |
| **Тип зберігання** | Об'єктне сховище (Object Storage). | Блочне сховище (Block Storage). | Файлове сховище (File Storage). |
| **Архітектура** | Безсерверна, доступна через API/HTTPS звідусіль. | Віртуальний жорсткий диск, примонтований до операційної системи EC2. | Спільна мережева папка (NFS) для багатьох інстанцій одночасно. |
| **Масштабування** | Автоматичне та безлімітне. | Потребує ручного налаштування розміру диска. | Еластичне, масштабується автоматично під час запису. |
| **Основні сценарії** | Роздача статичного контенту сайту, збереження бекапів, дата-лейки. | Системні диски ОС (Root volumes), бази даних, високі вимоги до IOPS. | Спільні диски для веб-серверів, робота з великими медіафайлами кількома серверами. |
