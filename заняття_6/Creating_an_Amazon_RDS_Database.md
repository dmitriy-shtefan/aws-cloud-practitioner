# Створення Amazon RDS Database

## Огляд і цілі

Традиційно створення database може бути складним процесом, який потребує участі database administrator або system administrator. У хмарі кількість кроків можна зменшити за допомогою Amazon Relational Database Service (Amazon RDS). У цій практичній роботі ви навчитеся використовувати Amazon RDS для розгортання MySQL database та виконання кількох базових адміністративних операцій.

На початку практичної роботи в навчальному середовищі Amazon Web Services (AWS) уже буде розгорнуто Amazon Elastic Compute Cloud (Amazon EC2) instance із запущеним вебзастосунком.

### Цілі

Після завершення цієї практичної роботи ви зможете:

- запускати MySQL database за допомогою Amazon RDS;
- налаштовувати вебзастосунок для підключення до Amazon Relational Database Service (Amazon RDS) for MySQL database instance;
- виконувати операції stop, start і reboot для database instance;
- здійснювати базовий моніторинг database.

Наприкінці практичної роботи ваша архітектура міститиме вебзастосунок на Amazon EC2, підключений до Amazon RDS for MySQL database instance.

### Передумови

Перед виконанням цієї практичної роботи необхідно завершити курс **Getting Started with Databases**.

## Обмеження сервісів AWS

У середовищі практичної роботи доступ до AWS services і service actions може бути обмежений лише можливостями, необхідними для виконання інструкцій. Під час спроби відкрити інші services або виконати дії, не передбачені цією практичною роботою, можуть виникати помилки.

## Завдання 1. Створення Amazon RDS database

У цьому завданні ви створите MySQL database у virtual private cloud (VPC). MySQL - це поширена open source relational database management system (RDBMS), тому плата за software license не стягується.

1. У верхній частині **AWS Management Console** введіть `RDS` у рядку пошуку.

   > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

2. У результатах пошуку виберіть **RDS**.
3. Виберіть **Create Database**.

Для параметра **Choose a database creation method** залиште вибраним значення за замовчуванням **Standard create**, щоб відобразити повний набір доступних функцій.

### Engine options

4. У розділі **Engine options** для параметра **Engine type** виберіть **MySQL**.
5. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

Тепер можна налаштувати database, зокрема software version, instance class, storage і параметри входу.

6. Відкрийте меню **Engine Version** і виберіть **MySQL 8.0.32**.
7. У розділі **Templates** виберіть **Dev/Test**.
8. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

Параметр Multi-AZ deployment автоматично створює replica database у другій Availability Zone для забезпечення high availability. Для цієї практичної роботи Multi-AZ deployment не потрібен.

9. У розділі **Availability and durability** виберіть **Single DB instance**.
10. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Settings

11. У розділі **Settings** у полі **DB instance identifier** введіть `inventory-db`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

12. У розділі **Credentials Settings** для параметра **Master username** залиште значення за замовчуванням `admin`.
13. У розділі **Credentials management** виберіть **Self managed**.
14. За допомогою смуги прокручування перейдіть до полів password.
15. У полі **Master password** введіть `sim-password!` малими літерами.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

16. У полі **Confirm master password** введіть `sim-password!` малими літерами.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

17. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Instance configuration

18. У розділі **Instance configuration** виберіть **Burstable classes (includes t classes)**.
19. Instance type автоматично зміниться на `db.t3.micro`. Залиште це значення.
20. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Storage

21. У розділі **Storage** відкрийте меню **Storage type**.
22. Виберіть **General Purpose SSD (gp2)**.
23. У полі **Allocated storage** введіть `20`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

24. Виберіть **Storage autoscaling**, щоб розгорнути цей розділ.
25. Зніміть прапорець **Enable storage autoscaling**.
26. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Connectivity

27. У розділі **Connectivity** для параметра **Compute resource** залиште значення за замовчуванням **Don't connect to an EC2 compute resource**. Підключення буде налаштовано вручну пізніше. Для параметра **Network type** також залиште значення за замовчуванням **IPv4**.
28. Відкрийте меню **Virtual private cloud (VPC)** і виберіть варіант, назва якого починається з **Lab VPC**.
29. Для параметра **DB subnet group** залиште значення за замовчуванням `rds-lab-db-subnet-group`.
30. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.
31. Для параметра **Public access** залиште значення за замовчуванням **No**.
32. Для параметра **VPC security group (firewall)** залиште значення за замовчуванням **Choose existing**.
33. У полі **Existing VPC security groups** натисніть **X** поруч із `default`, щоб видалити цю security group.
34. Відкрийте меню **Existing VPC security groups** і виберіть **DB-SG**. Виберіть будь-яке місце поза меню, щоб закрити його.
35. Для параметра **Availability Zone** залиште значення за замовчуванням **No preference**.
36. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Database authentication

37. Для параметра **Database authentication** залиште значення за замовчуванням **Password authentication**.

### Monitoring

38. У розділі **Monitoring** зніміть прапорець **Enable Enhanced Monitoring**.

Базові monitoring metrics і надалі будуть доступні для перегляду. Ви дослідите їх у завданні 3 цієї практичної роботи.

### Additional configuration

39. Виберіть **Additional configuration**, щоб розгорнути цей розділ.
40. У розділі **Database options** у полі **Initial database name** введіть `inventory`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

Це logical name database, яке використовуватиме застосунок.

41. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.
42. Для параметра **Encryption** зніміть прапорець **Enable encryption**.
43. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.

### Створення database

44. Унизу сторінки виберіть **Create database**.
45. У спливному вікні **Suggested add-ons for inventory-db** виберіть **Close**.

У верхній частині сторінки з'явиться повідомлення **Creating database inventory-db**.

Перш ніж переходити до наступного завдання, **Status** database instance має змінитися на **Available**. У live environment цей процес може тривати кілька хвилин.

46. Натисніть значок refresh.

Зверніть увагу, що database створено, але її **Status** має значення **Backing-up**.

47. Ще раз натисніть значок refresh.

Тепер **Status** database має значення **Available**, тому можна перейти до наступного завдання та підключитися до неї.

## Завдання 2. Налаштування взаємодії вебзастосунку з database instance

У середовищі практичної роботи автоматично розгорнуто Amazon Elastic Compute Cloud (Amazon EC2) instance із запущеним вебзастосунком. Щоб підключитися до застосунку, потрібно використати IP address цього instance.

У цьому завданні ви налаштуєте connection settings за допомогою застосунку. Ці параметри буде збережено в AWS Secrets Manager для подальшого використання.

### Відкриття вебзастосунку

48. Натисніть значок нещодавно відвіданих services поруч із рядком пошуку. Це значок із дев'ятьма білими квадратами, розташованими у три ряди по три.
49. Виберіть **EC2**.
50. На лівій навігаційній панелі виберіть **Instances**.

Зверніть увагу, що запущено instance під назвою **App Server**.

51. Виберіть instance **App Server**.
52. На вкладці **Details** натисніть значок copy під полем **Public IPv4 address**.
53. Щоб відкрити нову вкладку, натисніть знак плюс (**+**) у браузері.
54. На вкладці браузера виберіть поле URL і натисніть **Ctrl+V** на клавіатурі, щоб вставити IP address в address bar.

    > **Примітка.** Користувачі Mac також мають натиснути **Ctrl+V**. У цій практичній роботі клавіатура використовується як клавіатура Windows.

55. Щоб завантажити сторінку, натисніть **Enter** на клавіатурі.

Відкриється вебзастосунок. Він відображає мало інформації, оскільки застосунок ще не підключено до database.

56. Виберіть **Settings**.

Тепер можна налаштувати застосунок для використання Amazon RDS database instance, створеного раніше. Спочатку потрібно отримати database endpoint, щоб застосунок знав, як підключитися до database.

### Підключення вебзастосунку до database

57. Виберіть вкладку браузера **Instances**, але не закривайте вкладку **Inventory System**. Незабаром ви повернетеся до неї.
58. Натисніть значок нещодавно відвіданих services поруч із рядком пошуку.
59. Виберіть **RDS**.
60. На лівій навігаційній панелі виберіть **Databases**.
61. У стовпці **DB identifier** виберіть посилання `inventory-db`.
62. У розділі **Connectivity & security** знайдіть endpoint. Він має бути подібним до такого прикладу: `inventory-db.c7bo7sqp7mwn.us-east-1.rds.amazonaws.com`. Потім натисніть значок copy під полем **Endpoint**.
63. Виберіть вкладку браузера **Inventory System**.
64. Виберіть поле **Endpoint** і натисніть **Ctrl+V** на клавіатурі, щоб вставити щойно скопійований database endpoint.

    > **Примітка.** Користувачі Mac також мають натиснути **Ctrl+V**. У цій практичній роботі клавіатура використовується як клавіатура Windows.

65. У полі **Database** введіть `inventory`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

66. У полі **Username** введіть `admin`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

67. У полі **Password** введіть `sim-password!` малими літерами.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

68. Виберіть **Save**.

Застосунок збереже цю інформацію в Secrets Manager. Він підключиться до database, завантажить початкові дані та відобразить інформацію.

Тепер за допомогою вебзастосунку можна додавати, редагувати й видаляти інформацію про inventory.

Інформація про inventory зберігається в Amazon RDS for MySQL database, створеній раніше під час практичної роботи. Збій application server не призведе до втрати даних, а кілька application servers можуть отримувати доступ до тих самих даних.

### Зміна записів database

69. Щоб додати нові records до table, виберіть **+Add Inventory**.
70. У полі **Store** введіть `Atlanta`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

71. У полі **Item** введіть `Amazon Alexa`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

72. У полі **Quantity** введіть `7`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

73. Виберіть **Submit**.

Також можна редагувати наявні entries.

74. Натисніть значок edit поруч із **Puerto Rico** у верхньому рядку table.
75. У полі **Quantity** видаліть значення `12`, а потім введіть `5`.

    > **Примітка.** Щоб зафіксувати введене значення, натисніть **Enter** на клавіатурі або виберіть будь-яке місце поза полем введення.

76. Виберіть **Submit**.
77. Натисніть **X** на вкладці браузера **Inventory System**, щоб закрити її.

Ви успішно запустили застосунок і підключили його до database.

## Завдання 3. Моніторинг database instance

Моніторинг є важливою складовою підтримання reliability, availability і performance будь-якої database. Amazon RDS надає багато корисних metrics для моніторингу стану database instance. У цьому завданні ви дослідите деякі metrics створеного database instance.

78. На сторінці `inventory-db` виберіть вкладку **Monitoring**.
79. Щоб прокрутити сторінку вниз, скористайтеся смугою прокручування.
80. Перегляньте Amazon CloudWatch metrics, які відображають відповідні параметри database instance.
81. Продовжуйте прокручувати сторінку вниз, доки не переглянете всі доступні metrics.

## Завдання 4. Виконання операцій із database

У цьому завданні ви ознайомитеся з кількома адміністративними операціями, які можна виконувати з database в Amazon RDS.

82. На лівій навігаційній панелі виберіть **Databases**.
83. Виберіть database `inventory-db`.
84. Відкрийте меню **Actions**.

Меню **Actions** містить різні операції, зокрема **Stop temporarily**, **Reboot** та інші.

85. Щоб тимчасово зупинити instance, виберіть **Stop temporarily**. Database автоматично запуститься знову через 7 днів.
86. У спливному вікні **Stop DB instance temporarily** установіть прапорець у розділі **Acknowledgement**.
87. Виберіть **Stop temporarily**.

> **Примітка.** Після зупинення instance також припиняється нарахування плати за його роботу. Databases продовжують займати storage space, за який і надалі стягується плата.
