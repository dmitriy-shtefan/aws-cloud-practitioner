# **Billing, Pricing & Support**

---

## **1. Fundamentals of Pricing (Основи ціноутворення AWS)**

AWS використовує гнучку модель ціноутворення, яка дозволяє оптимізувати витрати залежно від типу навантаження та строків використання.

```
┌─────────────────────────────────────────────────────────────┐
│                 AWS PRICING FUNDAMENTALS                    │
├─────────────────────────────────────────────────────────────┤
│ • Metered Billing / Pay-as-you-go (no upfront, no lock-in)  │
│ • Compute Pricing Models (On-Demand, RIs, Savings Plans,    │
│   Spot, Dedicated)                                          │
│ • Tiered Pricing / Volume Discounts                         │
│ • AWS Free Tier (6 Months, Free with credits, Short-term)   │
└─────────────────────────────────────────────────────────────┘
```

### **Pay-as-you-go (Плата за фактом використання)**
AWS працює за моделлю вимірюваного виставлення рахунків (**Metered Billing**). Ви платите лише за ті ресурси, які реально споживаєте (посекундно або погодинно), без початкових авансових платежів та без обов'язкових довгострокових контрактів. 

### **Моделі ціноутворення для обчислень (EC2 Pricing Models):**
1.  **On-Demand Instances**: Оплата за фактом використання за секунди чи години без довгострокових зобов'язань та авансів. Підходить для короткочасних, непередбачуваних або нових проєктів.
2.  **Reserved Instances (RI)**: Фіксація зобов'язань щодо використання ресурсів на **1 або 3 роки** зі знижкою **до 75%**:
    *   *Standard RI*: Знижка до 75%, невикористані RIs можна перепродати на **Reserved Instance Marketplace**.
    *   *Convertible RI*: Знижка до 54%, дозволяє змінювати родина інстансів, ОС або тип за умови збільшення вартісного обсягу контракту.
    *   *Опції оплати*: **All Upfront** (все наперед — найбільша знижка), **Partial Upfront** (частина наперед) та **No Upfront** (щомісячна оплата зі знижкою).
3.  **Savings Plans**: Спрощена та гнучка альтернатива RIs, де ви фіксуєте суму погодинних витрат (наприклад, \$2/годину) на 1 або 3 роки:
    *   *Compute Savings Plans* (знижка до 66%): покриває EC2, **AWS Fargate** та **AWS Lambda** у будь-яких регіонах та сімействах.
    *   *EC2 Instance Savings Plans* (знижка до 72%): для конкретного сімейства інстансів у конкретному регіоні.
    *   *SageMaker Savings Plans* (знижка до 64%): для інстансів машинного навчання.
4.  **Spot Instances**: Дозвіл використовувати надлишкові (вільні) потужності AWS зі знижкою **до 90%**. AWS може примусово відібрати Spot-інстанс з 2-хвилинним попередженням. Якщо сервер вимикає AWS, остання неповна година не оплачується; якщо зупиняє користувач — ви платите за весь час.
5.  **Dedicated Hosts / Dedicated Instances**: Використання фізично виділеного заліза для вимог регуляторів чи перенесення власних ліцензій (**BYOL**).

### **Volume Discounts / Tiered Pricing (Оптові знижки)**
Чим більше ресурсів ви використовуєте, тим менше платите за одиницю споживання (**The more you use, the less you pay**). Це принципово для передачі даних (**Data Transfer Out**) та обсягів зберігання в **Amazon S3**.

### **AWS Free Tier (Безкоштовний рівень)**
Надає можливість тестувати та вивчати сервіси у трьох форматах:
*   **12 Months Free**: безкоштовно протягом першого року після реєстрації (наприклад, 750 годин EC2 t2/t3.micro та 750 годин RDS на місяць).
*   **Always Free**: безкоштовні ліміти, які не згоряють після 12 місяців (наприклад, 1 млн запитів AWS Lambda, 62,000 транзакційних листів в Amazon SES щомісяця).
*   **Short-term Trials**: короткі безкоштовні пробні періоди для конкретних сервісів з моменту їх першого активації.

## **2. Total Cost of Ownership (TCO) та фінансові інструменти оцінки**

**Total Cost of Ownership (TCO)** — це фінансова оцінка всіх прямих та непрямих витрат, пов'язаних із придбанням, впровадженням та експлуатацією інфраструктури протягом її життєвого циклу.

```
  On-Premise TCO (Visible & Hidden)           AWS Cloud TCO (OpEx)
┌──────────────────────────────────┐        ┌──────────────────────────────────┐
│ • Hardware & Software Licenses   │        │ • Metered Service Usage          │
│ • Real Estate & Facility Rent    │  ───►  │ • Cloud Support Plans            │
│ • Power, Cooling & Electricity   │        │ • Staff Training & Optimization  │
│ • IT Personnel & Maintenance     │        │ • No Data Center Overhead        │
└──────────────────────────────────┘        └──────────────────────────────────┘
```

### **Порівняння On-Premise та AWS Cloud (CapEx vs OpEx):**
*   **On-Premise (CapEx)**: Вимагає капітальних витрат на закупівлю серверів, мережевого обладнання, систем зберігання, оренду приміщень, оплату електроенергії, охолодження та утримання штату інженерів з обслуговування заліза.
*   **AWS Cloud (OpEx)**: Преобразує капітальні витрати на операційні (**OpEx**). Ви не купуєте залізо і платите лише за фактично спожиті хмарні метрики, позбавляючись від прихованих витрат на дата-центри (**undifferentiated heavy lifting**).

### **Фінансові та міграційні інструменти AWS:**
*   **AWS Pricing Calculator** (`calculator.aws`): Безкоштовний онлайн-калькулятор у веб-браузері, який дозволяє змоделювати та розрахувати приблизні щомісячні та річні витрати на сервіси AWS без необхідності входу в акаунт. Результати оцінки можна експортувати у CSV-файл або поділитися ними за публічним посиланням.
*   **Migration Evaluator (колишній TCO Logic)**: Спеціалізований сервіс для бізнесу, який використовує безагентний збирач даних (**agentless collector**) в локальній інфраструктурі компанії для аналізу наявних залізних витрат і формування точного фінансового обґрунтування міграції в хмару.
*   **Допоміжні сервіси міграції**:
    *   **AWS Database Migration Service (DMS)** & **AWS Schema Conversion Tool (SCT)**: для міграції баз даних.
    *   **VM Import/Export**: для безкоштовного імпорту віртуальних машин (VMware, Hyper-V) у вигляді **AMI** в EC2.

## **3. AWS Organizations та Consolidated Billing**

**AWS Organizations** — це сервіс централізованого управління та адміністрування багатьма акаунтами AWS.

```
                     ┌───────────────────────────┐
                     │   Root / Payer Account    │
                     │  (Consolidated Billing)   │
                     └─────────────┬─────────────┘
                                   │
               ┌───────────────────┴───────────────────┐
               ▼                                       ▼
    ┌────────────────────┐                  ┌────────────────────┐
    │     OU: Dev        │                  │     OU: Prod       │
    │  [SCP: Restrict]   │                  │  [SCP: FullAccess] │
    ├────────────────────┤                  ├────────────────────┤
    │ • Dev-Account-1    │                  │ • Prod-Account-1   │
    │ • Dev-Account-2    │                  │ • Prod-Account-2   │
    └────────────────────┘                  └────────────────────┘
```

### **Компоненти структури AWS Organizations:**
1.  **Management / Payer Account**: Головний (кореневий) акаунт організації, з якого здійснюється платіж за всі інші акаунти.
2.  **Member Accounts**: Дочірні акаунти, які входять до складу організації.
3.  **Organizational Units (OUs)**: Логічні групи акаунтів (наприклад, `Dev`, `Test`, `Prod`), що дозволяють застосовувати спільні правила управління.
4.  **Service Control Policies (SCPs)**: Централізовані політики управління доступом у JSON-форматі, які задають максимальні межі дозволених дій (**permission boundaries**) для всіх акаунтів у всій організації або окремих OUs. 
    *   *Важливо*: SCPs діють навіть на **Root User** членських акаунтів!

### **Consolidated Billing (Консолідована оплата)**
Безкоштовна функція в AWS Organizations, яка об'єднує витрати всіх членських акаунтів в єдиний спільний платіжний документ для Payer Account:
*   **Спільні оптові знижки**: Споживання ресурсів (наприклад, S3 або Data Transfer) з усіх акаунтів сумується разом. Це дозволяє набагато швидше досягати порогів оптових знижок (**volume pricing discounts**) та економити кошти.
*   **Спільні RIs та Savings Plans**: Зарезервовані інстанси чи Savings Plans, куплені в одному акаунті, можуть автоматично покривати споживання ресурсів в інших акаунтах організації.

## **4. AWS Billing and Cost Management (Інструменти контролю витрат)**

AWS надає набір інструментів для прозорого аналізу, сповіщення та контролю витрат:

### **1. AWS Budgets**
Інструмент для встановлення кастомних бюджетів та сповіщень при наближенні або перевищенні встановлених лімітів.
*   **Типи бюджетів**: **Cost Budget** (за грошовими витратами), **Usage Budget** (за обсягом споживання ресурсів) та **Reservation / Savings Plans Budget** (за відсотком утилізації зарезервованих потужностей).
*   **Ліміти**: Перші **2 бюджети є повністю безкоштовними**.
*   **Сповіщення**: Надсилаються на email або через **Amazon SNS** при досягненні фактичного або прогнозованого (**forecasted**) порогу.

### **2. AWS Cost Explorer**
Інтерактивний графічний інструмент у консолі для візуалізації, аналізу, детальної фільтрації та прогнозування витрат у часі.
*   Дозволяє групувати витрати за сервісами, регіонами, акаунтами або тегами.
*   Містить вбудований механізм прогнозування майбутнього рахунку на основі попередньої історії споживання.
*   Розміщується глобально у регіоні `us-east-1`.

### **3. AWS Cost and Usage Report (CUR)**
Найбільш детальний та повний звіт про витрати й використання ресурсів AWS.
*   Автоматично генерує та зберігає CSV або Parquet файли в бакет **Amazon S3**.
*   Дані з CUR можна аналізувати через **Amazon Athena** за допомогою SQL-запитів та візуалізувати в **Amazon QuickSight**.

### **4. CloudWatch Billing Alarms**
Традиційний спосіб моніторингу за допомогою створення алармів у CloudWatch. Для його роботи необхідно попередньо увімкнути опцію **"Receive Billing Alerts"** у налаштуваннях платіжного профілю.

### **5. Cost Allocation Tags**
Метадані у вигляді пар "ключ-значення" (наприклад, `Environment: Production`, `CostCenter: Marketing`), які прив'язуються до ресурсів. Після активації в розділі Billing вони дозволяють розбивати та деталізувати витрати за конкретними проєктами чи відділами у звітах Cost Explorer та CUR.

## **5. AWS Support Plans та супутні сервіси підтримки**

AWS пропонує 4 рівні планів підтримки для вирішення технічних та бізнес-питань:

| Характеристика | Basic | Developer | Business | Enterprise |
| :--- | :--- | :--- | :--- | :--- |
| **Ціна** | Безкоштовно | Від **\$29/міс** (або 3% від споживання) | Від **\$100/міс** (або % від споживання) | Від **\$15,000/міс** |
| **Призначення** | Для вивчення та тестування | Для розробки та експериментів | Для продакшен-навантажень | Для критично важливих систем бізнесу |
| **Канали зв'язку** | Документація та фолбек на Billing Support | Email у робочий час | **24/7** Email, чат та телефон | **24/7** Email, чат та телефон |
| **Час реагування (SLA)** | Немає технічного SLA | General: <24h<br>System impaired: <12h | Production impaired: **<4h**<br>Production down: **<1h** | Business critical down: **<15 хв** |
| **Trusted Advisor** | 7 базових перевірок | 7 базових перевірок | Повний набір перевірок | Повний набір перевірок |
| **Персональна підтримка** | Немає | Немає | Немає | **TAM** + **Support Concierge Team** |

### **AWS Technical Account Manager (TAM)**
Спеціалізований персональний технічний консультант від AWS, який доступний **виключно на рівні Enterprise Support**.
*   TAM надає проактивне керівництво, допомагає проектувати архітектури відповідно до Well-Architected Framework, проводить внутрішні навчальні сесії (**brown bag sessions**) та оптимізує витрати.

### **AWS Trusted Advisor**
Інструмент автоматизованого моніторингу та оцінки акаунта на відповідність найкращим практикам AWS. 

Перевірки розподілені за **5 категоріями**:
1.  **Cost Optimization**: виявлення недіяльних балансувальників чи невикористовуваних Elastic IPs.
2.  **Performance**: аналіз високого завантаження EC2 чи оптимізація баз даних.
3.  **Security**: перевірка наявності MFA на Root User, відкритих публічних S3-бакетів чи незахищених Security Groups.
4.  **Fault Tolerance**: перевірка наявності автоматичних бекапів RDS та реплікації.
5.  **Service Limits**: сповіщення про наближення до системних лімітів акаунта (квот).
