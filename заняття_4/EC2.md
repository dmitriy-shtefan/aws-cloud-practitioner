# **Compute — Amazon EC2 (Elastic Compute Cloud)**

---

## **1. Amazon EC2 Instances**

**Amazon EC2 (Elastic Compute Cloud)** — це вебсервіс, який надає масштабовані та безпечні обчислювальні потужності у вигляді віртуальних машин (VM) у хмарі AWS. 

*   **Backbone of AWS**: EC2 вважається технологічною основою («хребтом») більшості сервісів AWS, оскільки більша частина служб (навіть безсерверних, як-от S3, RDS чи Lambda) у глибині своєї архітектури працює на базі серверів EC2.
*   **Virtual Machine (VM)**: Коли ми запускаємо віртуальну машину в EC2, ми називаємо її **Instance** (інстанс). Це програмна емуляція фізичного комп'ютера, яку можна легко створити, скопіювати, масштабувати або перенести.
*   **Shared Tenancy**: За замовчуванням інстанси використовують модель **multi-tenant** (спільна оренда), коли кілька віртуальних машин різних клієнтів можуть фізично працювати на одному залізі. При перевантаженні або перезапуску ваш інстанс може фізично переміститися на інший сервер у дата-центрі.

## **2. Amazon Machine Image (AMI) та Instance Types**

Для створення та налаштування інстансу вам необхідно вибрати дві речі: **операційну систему (образ)** та **потужність заліза**.

### **Amazon Machine Image (AMI)**
**AMI** — це попередньо налаштований шаблон для віртуальної машини, що містить операційну систему, сервери додатків та необхідні бінарні файли.
*   **AMI ID є регіональним (Regional-based)**: Один і той самий образ (наприклад, Amazon Linux 2) у різних регіонах AWS матиме унікальний та відмінний ідентифікатор **AMI ID**.
*   **Архітектура**: Образи підтримують 64-бітні варіанти архітектури **x86** або енергоефективні процесори **ARM**.
*   **Джерела AMI**:
    *   *Quick Starts*: стандартні ОС, які підтримує AWS (Amazon Linux 2, Ubuntu, Windows Server, Red Hat, SuSE тощо).
    *   *AWS Marketplace*: комерційні образи з уже встановленим ліцензійним софтом від сторонніх розробників.
    *   *Community AMIs*: безкоштовні образи, створені та надані спільнотою.
    *   *Custom AMIs (My AMIs)*: створені вами власні образи (наприклад, ви налаштували вебсервер Apache, «запекли» його в AMI та зберегли для майбутнього автоматичного розгортання).

### **Instance Types & Families (Типи та сімейства інстансів)**
AWS групує інстанси у **Instance Families** (сімейства) залежно від типу фізичного заліза та їхньої архітектурної спеціалізації. Кожне сімейство розраховане на певні бізнес-вимоги:

1.  **General Purpose** (Загальне призначення: серії **T2, T3, M5, Mac**): Збалансоване співвідношення обчислювальної потужності (CPU), пам'яті (RAM) та мережевих ресурсів. Ідеально підходить для вебсерверів, репозиторіїв коду або середовищ розробки.
2.  **Compute Optimized** (Оптимізовані для обчислень: серія **C**): Високопродуктивні процесори для обчислювально важких завдань. Використовуються для наукового моделювання (scientific modeling), виділених ігрових серверів (gaming servers) або систем доставки реклами (ad servers).
3.  **Memory Optimized** (Оптимізовані для пам'яті: серія **R**): Призначені для швидкої обробки великих наборів даних у пам'яті (RAM). Використовуються для високопродуктивних кешів (in-memory caches), баз даних або систем реального часу (real-time big data analytics).
4.  **Accelerated Computing** (Прискорені обчислення: серії **P2, P3, P4**): Використовують додаткові апаратні прискорювачі та графічні процесори (**GPUs**), а також кастомні чіпи AWS (наприклад, **AWS Inferentia** чи **AWS Trainium**). Сценарії: машинне навчання (ML), deep learning, 3D-рендеринг та фінансове моделювання.
5.  **Storage Optimized** (Оптимізовані для збереження: серія **I**): Висока швидкість послідовного читання та запису (high sequential read/write) на локальні накопичувачі. Сценарії: великі NoSQL бази даних, дата-склади (data warehousing).

#### **Instance Size (Розмір інстансу):**
Розмір вказує на кількість віртуальних ядер процесора (vCPU) та RAM. Схема іменування зазвичай виглядає як `t2.micro`, де `t2` — це сімейство, а `micro` — розмір. Розміри зазвичай масштабуються за ступенем двійки: **nano, micro, small, medium, large, xlarge, 2xlarge** тощо. При збільшенні розміру інстансу його характеристики та годинна вартість приблизно подвоюються.

*   **Bare Metal**: Особливий варіант інстансів (наприклад, `m5.metal`), які запускаються безпосередньо на фізичному залізі без використання гіпервізора (hypervisor) для максимального контролю та швидкості.

## **3. Amazon EBS Volumes (Elastic Block Store)**

**Amazon EBS** — це сервіс, який надає віртуальні диски для постійного блочного зберігання даних (**persistent block storage**), які ви монтуєте до інстансів EC2.

*   **Block Storage**: Дані розбиваються на однакові блоки та обробляються безпосередньо операційною системою без накладання ієрархії папок.
*   **Single Write Volume**: EBS-том зазвичай розрахований на підключення лише до одного інстансу EC2 одночасно (підтримує модель *single write*).
*   **Типи EBS**: існують твердотільні накопичувачі (**SSD**) для високих вимог до IOPS та магнітні диски (**HDD**) для високої пропускної здатності. Найбільш збалансованими за ціною та продуктивністю є томи **GP2 / GP3** (General Purpose SSD).
*   **EBS Snapshots**: Резервні копії EBS-томів, які зберігають стан диска на певний момент часу. Вони є інкрементними та дозволяють легко відновлювати дані або створювати нові диски.
*   **Encryption**: EBS підтримує шифрування диска «з коробки» за допомогою ключів KMS. Найкраща практика — вмикати шифрування під час створення тому.
*   *Різниця з Root Volume*: Диск, на якому встановлена сама операційна система інстансу, називається **Root Volume**. Він має певні обмеження щодо вибору типів накопичувачів порівняно зі звичайними додатковими томами даних.

## **4. Key Pairs та Security Groups**

Доступ до серверів та захист їхнього трафіку є ключовими завданнями безпеки клієнта в хмарі.

### **Key Pairs (Пари ключів)**
Це криптографічний метод авторизації для віддаленого входу на сервери за допомогою технології асиметричного шифрування.
*   Складається з двох частин: **Public Key** (публічний ключ, який AWS записує на сам сервер) та **Private Key** (приватний ключ у вигляді файлу `.pem`, який ви завантажуєте на свій комп'ютер і зобов'язані тримати в таємниці).
*   Для успішного підключення через **SSH** на Linux необхідно встановити суворі права доступу на `.pem` файл на вашому комп'ютері за допомогою команди `chmod 400 <назва_ключа.pem>` (файл має бути доступний тільки для читання вашим користувачем).
*   Для підключення до Windows-серверів за допомогою клієнта **RDP** приватний ключ використовується для дешифрування початкового адміністраторського пароля.
*   **Альтернатива (Session Manager)**: Найбільш безпечний спосіб підключення — **AWS Systems Manager (SSM) Session Manager**. Він дозволяє підключатися до консолі інстансу прямо через браузер без необхідності використовувати відкриті SSH-порти (22) або завантажувати ключі доступу (вимагає наявності встановленого **SSM Agent** та прив'язаної до інстансу **IAM Role** з політикою `AmazonSSMManagedInstanceCore`).

### **Security Groups (Групи безпеки)**
Це віртуальний фаєрвол, який контролює вхідний (**inbound**) та вихідний (**outbound**) трафік безпосередньо на рівні конкретного інстансу EC2.
*   **Implicit Deny**: За замовчуванням весь вхідний трафік повністю заборонений. Ви можете створювати **лише правила дозволу (Allow rules)**. Правила заборони (Deny rules) у Security Groups створити неможливо.
*   **Stateful (Збереження стану)**: Якщо ви дозволили певний вхідний трафік (наприклад, вхід на порт 80 для вебсайту), згенерований у відповідь вихідний трафік буде випущений системою автоматично, незалежно від налаштувань вихідних правил.
*   **Неможливо заблокувати окрему IP-адресу**: Через те, що Security Groups не підтримують правила заборони (Deny), заблокувати один конкретний шкідливий IP в них не можна (для цього слід використовувати **Network Access Control Lists (NACLs)** на рівні підмережі).
*   **Налаштування**: Ви можете відкривати порти, такі як `22` (SSH), `80` (HTTP), `443` (HTTPS) або `3389` (RDP). Назву Security Group неможливо змінити після створення.

## **5. Стани EC2 Instance: Start, Stop, Reboot і Terminate**

Життєвий цикл інстансу керується за допомогою наступних станів:

*   **Start (Запуск)**: Запуск інстансу в роботу. Інстанс завантажується та отримує нову динамічну публічну IP-адресу з пулу адрес AWS.
*   **Stop (Зупинка)**: Тимчасове вимикання віртуальної машини. **УВАГА**: При зупинці та подальшому запуску інстансу його публічний IP-адрес обов'язково зміниться!
    *   *Рішення*: Якщо вам потрібен постійний статичний IP, який не буде змінюватися при зупинках сервера, необхідно зарезервувати та прив'язати до інстансу **Elastic IP (EIP)**.
*   **Reboot (Перезавантаження)**: Звичайне перезавантаження ОС. При перезавантаженні інстанс фізично не переміщується на інший сервер і **повністю зберігає свою поточну публічну IP-адресу**.
*   **Terminate (Знищення)**: Повне та безповоротне видалення віртуальної машини та її ресурсів з хмари. За замовчуванням EBS-том, який виконував роль Root Volume, також автоматично видаляється разом з інстансом.

## **6. Моделі ціноутворення (EC2 Pricing Models)**

AWS надає гнучкі фінансові моделі, що дозволяють суттєво оптимізувати витрати залежно від вашого навантаження:

```
┌─────────────────────────────────────────────────────────────────┐
│                       EC2 Pricing Models                        │
├───────────────────┬───────────────────┬─────────────────────────┤
│   MODEL           │   SAVINGS         │   BEST FOR              │
├───────────────────┼───────────────────┼─────────────────────────┤
│ • On-Demand       │   Baseline        │ Short-term / Unpredict. │
│ • Reserved (RI)   │   Up to 75%       │ Steady-state / 1-3 yrs  │
│ • Savings Plans   │   Up to 72%       │ Flexible family commit. │
│ • Spot            │   Up to 90%       │ Interruptible / Batch   │
│ • Dedicated Host  │   Expensive       │ BYOL / Compliance       │
└───────────────────┴───────────────────┴─────────────────────────┘
```

### **1. On-Demand Instances (На вимогу)**
*   Модель оплати за фактом використання (**Pay-as-you-go**), яка діє за замовчуванням.
*   **Тарифікація**: Посекундна оплата (мінімум 60 секунд) для Linux та Windows інстансів або погодинна для деяких інших ОС.
*   **Переваги**: Максимальна гнучкість, немає жодних початкових платежів (no upfront) та довгострокових зобов'язань.
*   **Сценарії**: Короткочасні, непередбачувані або пікові навантаження, які не можна переривати. Також чудово підходить для перших запусків та тестування нових додатків.

### **2. Reserved Instances (Зарезервовані інстанси / RIs)**
*   Ви фіксуєте зобов'язання використовувати певну кількість обчислень протягом **1 або 3 років**, натомість отримуючи знижку **до 75%** порівняно з On-Demand.
*   **Класи RIs**:
    *   *Standard RI*: Максимальна знижка (до 75%), але обмежені можливості зміни конфігурації (можна міняти лише AZ, розмір у межах Linux-сімейства тощо). Невикористані Standard RIs можна перепродати на спеціальному публічному ринку **RI Marketplace** (недоступно для GovCloud-регіонів).
    *   *Convertible RI*: Менша знижка (до 54%), але дозволяє обмінювати поточний RI на інший з іншими характеристиками (родина інстансів, ОС, тенентність), якщо новий контракт має рівну або більшу фінансову вартість.
*   **Опції оплати**: All Upfront (вся сума наперед — найбільша знижка), Partial Upfront (частина наперед) та No Upfront (щомісячна оплата за зниженим тарифом протягом усього контракту).
*   **Область дії (Scope)**:
    *   *Regional RIs*: Знижка діє на весь регіон, надає гнучкість у межах розмірів сімейства (instance size flexibility), але **не гарантує** резервування фізичної ємності в конкретному дата-центрі.
    *   *Zonal RIs*: Знижка жорстко прив'язується до конкретної AZ, **гарантує резервування фізичної ємності** (capacity reservation), але не має гнучкості щодо зміни розміру інстансів.

### **3. Savings Plans**
*   Сучасна та значно спрощена альтернатива Reserved Instances. Замість бронювання конкретних типів інстансів ви зобов'язуєтеся витрачати певну фіксовану суму грошей на годину (наприклад, \$2/hour) протягом **1 або 3 років**.
*   **Види Savings Plans**:
    *   *Compute Savings Plans* (знижка до 66%): Максимально гнучкий план. Автоматично застосовується до обчислень незалежно від типу інстансу, регіону, операційної системи, тенентності, а також покриває використання безсерверних технологій **AWS Fargate** та **AWS Lambda**!
    *   *EC2 Instance Savings Plans* (знижка до 72%): Надає найнижчі ціни в обмін на зобов'язання використовувати конкретне сімейство інстансів (наприклад, сімейство M5) у конкретному регіоні. Ви все ще можете вільно змінювати операційну систему, розмір або тенентність у межах цього сімейства.
    *   *SageMaker Savings Plans* (знижка до 64%): покриває використання інстансів сервісу машинного навчання SageMaker.

### **4. Spot Instances**
*   Дозволяють використовувати **надлишкові (вільні) обчислювальні потужності AWS** із колосальною знижкою **до 90%** порівняно з On-Demand.
*   **Головний ризик**: AWS має право в будь-який момент примусово відібрати у вас сервер (з 2-хвилинним попередженням), якщо ця потужність знадобиться On-Demand клієнтам.
*   *Правило оплати при перериванні*: Якщо AWS примусово вимикає ваш Spot-інстанс, ви не оплачуєте останню неповну годину його роботи. Якщо ж ви самі зупините або видалите Spot-інстанс, ви будете зобов'язані оплатити кожну секунду або годину, яку він встиг пропрацювати.
*   **Сценарії**: Робочі навантаження з гнучким часом старту й фінішу, які легко переносять переривання (наприклад, пакетна обробка даних через **AWS Batch**, фонові математичні розрахунки, черги завдань).

### **5. Dedicated (Виділені сервери)**
*   **Dedicated Instances**: Інстанси запускаються на фізично виділеному залізі, ізольованому від інших клієнтів AWS. Проте інстанси вашого власного акаунта можуть ділити цей спільний фізичний хост. Тарифікується за кожен інстанс плюс додаткова фіксована регіональна плата.
*   **Dedicated Hosts**: Фізичний сервер повністю у вашому одноосібному розпорядженні. Надає повну видимість фізичних характеристик заліза (кількість сокетів, ядер, host ID).
    *   *BYOL (Bring Your Own License)*: Це єдиний варіант, який дозволяє вам перенести у хмару власні корпоративні ліцензії (наприклад, Microsoft SQL Server або Windows Server), які юридично прив'язані до кількості фізичних ядер чи сокетів процесора. Це найдорожчий варіант хостингу в EC2.
